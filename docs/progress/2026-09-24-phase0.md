- Notes:
  - **Script object references are raw addresses.** `TVarEC` of kind
    `vkDword` holds object pointers (`PtrUInt`), and the save writes them
    truncated to 32 bits. Saves therefore contain heap addresses, which change
    every run, and a loaded save holds dangling values until scripts reassign
    them. The hash writes them through the unused `SnapshotObjectIdentity`
    hook as `star:/planet:/ship:/item:<id>` or script-owned `script:N:<list>:I`.
    Values `>= $10000` that match no collected object are written as
    `unresolved` and counted (13–30 per turn on the late save; `quest_item`
    is one). Either a container is missing from `CollectIdentities` or they
    point at freed objects. Worth resolving before Phase 5 snapshots.
  - Loading recomputes derived values (`AverageRangerCapital`,
    ranger strengths), so a game-written save differs from its re-save; the
    round trip therefore starts from a loaded game.
  - Every load appends a `SaveLoaded` galaxy event; the round trip drops it.
  - `TGalaxy.Create` calls `Randomize`; the runner pins `System.RandSeed`
    after loading. Changing `--sim-seed` did not change 5 turns of hashes, so
    the parked simulation did not visibly draw from the shared stream there.
  - Mod `OnSave` handlers run inside `SaveToBuffer`, so hashing could affect
    state with mods that mutate it. Stock data has none.
  - Cost: 100 turns take about 14 s on the debug build; the full
    `tools/test.py` run on three saves about 45 s.
  - Unit tests: every requested unit reaches `GR_Main` → `Globals`, so the
