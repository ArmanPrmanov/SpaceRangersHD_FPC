## How a race arises

Between days, a client's command runs at once on its own copy (the prediction). The host queues it and applies it at the end-turn barrier, in `Session.Humans` order. The host's own commands run at once. Two humans acting on the same object in the same period act on different copies, and the host applies them in its order. Remote-dialogue commands run on the host's turn thread as they arrive.

**Step C** (planned, owner's decision) changes trades only. The host applies a trade as soon as it arrives between days and answers the client at once. The client waits for that answer instead of predicting. The host relays accepted trades to the other clients at the same location.

The discarded first attempt also applied a peer's queued non-trade commands early and relayed every command kind. That moves the B and C bugs below onto the host's open screens and onto other clients. Step C must apply and relay trades only.

## Details

### Script builtins acting on the wrong machine or human

- **B1. Modal and screen builtins.** None of these check `ScriptHuman = LocalHuman`:
  - modal boxes: `SF_MessageBox` (15766), `SF_MessageBoxYesNo` (15787), `SF_CountBox` (15844), NumberBox (15905), TextBox (15953), ListBox (15992), custom dialogs (16824);
  - screen changes: FormChange and RunChildForm (16692–16770), and `SF_StartVideo` (closes the current screen, then waits on music in `Sleep` loops, 12075–12125);
  - `SF_FormShipCurItem` (16586–16670): frees or replaces the local human's held item.

  Item, dialog, auxiliary, UI and turn code all reach them from command paths: ScriptItemsAct, UseItem/UseHeld*, the government, station and talk dialog commands, RunUiCode, and Takeoff/RunScriptTurns (every script's turn code). On the host this shows a client's modal to the host's player. It blocks the UI thread, or the turn thread in a remote dialogue, the same failure as the goods message box fixed in `d15ee13`.
  Fix: return the default answer when `ScriptHuman` is not local. Never show UI on the turn thread. A real remote prompt would need a request/answer protocol like Remote dialogue.
- **B2. Dialog text builtins.** `SF_DText`, `SF_DAddText`, `SF_DAnswer` and InjectAnswer pick the ruins-talk, talk or government screen from **`LocalPlayer`**'s location and write its text and choices. `DAnswer` also does:
  - `'exit'`: `LocalPlayer.CloseRuinsModeScreen`;
  - `'main'`: `RuinsTalkScreen.M_Main` or `TalkScreen.CodeMsgOut`, which dereferences a nil `LocalHuman.TalkShip` (fTalk.pas 1923, S) or submits nested commands as the host;
  - `'exit_end'`: `Session.GameEndReason := 4`.

  The dialog state is single and global: `Session.ScriptDialogIndex`, `CurrentScript`, `ScriptDialogInjections`, `ScriptDialogOverrides`. A client's dialog applied while the host has its own dialogue open overwrites it, and can free injections the host's choices still point to (S).
  Fix:
  - branch on `ScriptPlayer`, and touch screens only when `ScriptHuman = LocalHuman`;
  - move the dialog state into `THuman`, or save and restore it around remote commands;
  - never relay dialog or script commands.
- **B3. CloseBridge.** `ExecuteCloseBridge` calls `CloseRuinsModeScreen`, which sets `RequestedScreenId` and closes the current screen of whichever machine runs it. Fix: split it into a state part for the actor and a screen request made only for the local actor.
- **C1. Talk builtins.** `SF_GetTalkShip`, `SF_TalkByAI` and `SF_GetTalkType` read `LocalHuman.TalkShip/TalkScripted/TalkType`. For a client's talk on the host, they return the host's fields, usually nil. Fix: read `ScriptHuman`'s fields, falling back to `ActingHuman`'s.
- **C2. Takeoff and end-turn requests.** `SF_ExtremalTakeOff` and `SF_ForceNextDay` set the unit globals `ScriptTakeoffRequested` and `ScriptEndTurnRequested`. The host's `TryDispatchScriptTakeoff` and `TryDispatchScriptEndTurn` then act on `LocalPlayer`. A client's `OrderScriptTakeoff` or `ClearScriptEndTurn` clears the host's own pending request (aUiScriptActions.pas 187, 202). Fix: keep the requests per `THuman` and dispatch only the local one.
- **Nested commands.** `NewCommand` always stamps `LocalPlayer` as the actor (aCommands.pas 165–172, S). A command that script code submits while running for a remote human therefore acts for the host. Fix: stamp `ScriptHuman`'s player while a command runs.
- **Queued battles and videos.** `SF_StartAB`, `SF_StartRobots` and the video queue act "on this machine, whoever the script's human is" (aScriptFun.pas 8162–8195, 12118). The host's human plays the client's battle. The client plays it too and sends `FinishQueuedPlanetaryBattle`, which the host applies to its own queue. Fix: queue per human, and decline or forward a remote human's request.
- **Other `LocalPlayer` reads (low).** Takeoff and FinishTerronBattle set the galaxy's dominator surfaces from `LocalPlayer` (aPlayerActions.pas 919, aPlanetActions.pas 1001–1022). The host's `AfterburnerStopCondition` setting applies to every human (aGalaxy.pas 2965).

### Shared objects between days

- **BuildPirateShip (critical).** Parts are found through the global `Galaxy.IdToItem` and paid for before anything checks that they are still in the shop, hold or storage. A builds with shop item X first. Then B's build either adds X to a second ship (double ownership, a double free later), or `EquipmentShop.Delete(IndexOf(X) = -1)` raises after money and earlier parts have moved. Fix: check every part's source and owner first; raise `rrItemGone`.
- **Selling to an NPC in space.** The sell side of `TradeGoods` changes the partner's money and cargo before `SellGoodsToLocation`'s own check (aShip.pas 7458), and never checks that the partner can pay. Two humans sell to the same trader: its money clamps at 0 and both are paid in full. A refused sale also leaves the partner changed. The buy side is correct (`CheckGoodsPurchase` against `TradeRows`). Fix: check the partner's money and the seller's cargo first; raise `rrNoMoney`.
- **BuySpecialShip.** `SpecialServiceActive := False` is set but never checked first, so both humans get the SuperHull. Fix: refuse when it is not active.
- **RequestProtection (S).** It casts `X.OrderTarget` to `TShip` unchecked. After A's request the target can be nil or a planet, so B's request crashes the host. Fix: refuse unless it is a `TShip`.
- **RunDominatorProgram (S).** There is no "already hacked" check and no program-count check, so two humans hack one dominator and Shipwreck drops its loot twice. Fix: refuse if a program was already applied or none is left.
- **BuyMap.** The screen checks `FindUnchartedNeighborConstellation` on the client's copy; the host deducts money and then reveals whatever is uncharted now, or dereferences nil. Separately, the map is galaxy-wide (`Constellation.Visible`), so one human's purchase reveals it to all; that is a design point. Fix: carry the constellation id, refuse before charging.
- **Station offers and orders.**
  - BuySatellite takes whatever offer was regenerated after A's purchase, with no money check (1585–1589).
  - Invest does not re-check the screen's rules, so two humans create two identical stations (1913–1919).
  - RelocateDominion, OrderPirateAmbush and OrderPirateAssault: both pay, the last order wins, and two relocations leave two stars pointing at the Dominion (S).
  - Fix: carry the offer or target and the quoted price; revalidate; refuse when stale or when money is short.
- **A sponsored station's ship (S).** OpenShipScreen, CloseShipScreen and TrainSkill swap `FreeExperience` between the actor and the ship (aHoldActions.pas 742–747, 818–823, 3329–3331), so two humans interleaving swap experience. Hold cells are named by index, and a stale TakeHoldEntry sets the held item before `Delete(-1)` raises (499–504): a duplicate-item risk. Fix: only one editor per ship, and hold cells by item id.
- **Scripts by index.** `ScriptAnswer`, the `ScriptCallDialog*` commands and the government, station and talk dialog commands name `Galaxy.Scripts` by index. Each machine appends the scripts its own commands start, so the index differs on the host and B's answer runs another script's code. Injected answers (`ScriptDialogInjections`) are also by index, into a list each machine rebuilds from code that reads `LocalHuman.TalkShip`. The override commands read `ScriptDialogOverrides[0]` without a count check (S). Fix: a stable script id, and injections named by script and answer.
- **TreatDisease 3** turns off the saved galaxy flag `GraphDominatorSurfacesEnabled` for every human. Fix: make the effect per human.
- **Surface loot** is named by index plus id (aPlanetActions.pas 1186–1270). After A takes entry 0, B's pickup of a still-present item is refused, as `rrOther`. Safe, but wrong. Fix: find by id, raise `rrItemGone`.

### Low

- **Possibly costing more than shown, with no money check:** PayForModernization (the second payer gets nothing), ChangeSide and OrderPirateRaid (priced up to 1.5× the quote), BuyPirateNodes on an exhausted reserve.
- **No money check:** RepairHeld and RepairAll (aHoldActions.pas 2749, 2899), PayBribe. `SetMoney` clamps to 0..1e8, so this means "pay what you have".
- **Can create money:** gifts to partners (the NPC gets the full amount), and OpenDeposit, which keeps `DepositAmount` while the payment is clamped (aStationActions.pas 1821–1825).
- **Truces:** one `TruceShip` field, so B's truce silently replaces A's paid one.
- **No owner check:** any ship's medals can be reordered; RecallInterceptors.
- **Client input trusted:** `EquipmentConfigurations[Index]` has no bounds check (aPlayer.pas 3874); `SetQuestMoney` sets money from the argument (text quests only); `SetSessionFlag` is accepted from any peer.
- **Global flags set by one human:** `Session.LastLoadedPlayerName` (ChangeNationality), `Galaxy.ScoreScreenDismissed`, `Ship.DaysSincePlayerSeen` (one per ship, not per human).
- **Result globals** (`PlanetOutcome`, `EquipmentPurchase`/`PurchasedItem`, `TalkOutcome`, `Station*`, `Sale*` and others) are read right after `SubmitCommand`. They are safe while nothing applies a remote command between a submit and its read. Step C must keep that true: apply only under `MayChangeUnderScreen`.

### Checked and safe

- **The hangar.** `HangarShipIds` is a display cache. Hulls for sale go through BuyEquipment by id. A stored hull is the buyer's own.
- **Storage and the held item.** Storage is per ranger. The held item only ever comes from the edited ship or the actor's own storage.
- **Sales** only add to the shared list, then call `ShopStockChanged`.
- **The bank, medical, science and military services:** per actor.
- **Partners.** `PartnerShip <> nil` refuses the second human, so one NPC never partners two humans. A pirate re-accept may add a duplicate `PiratePartners` entry (aPirate.pas 2394, S).
- **DemandMoney, DemandCargo, PayPrisonBail:** the host checks the NPC, and the second human gets nothing.
- **Government quests.** `GenerateQuestOffer` is a pure function of the planet and the turn, and each human keeps its own offer and quest. Two humans can take the same quest and both earn its reward; this is design, not a race. Kill-ship quests send both after the same NPC; whether the second human's quest then fails is not checked.
- **Orders, EndTurn, HoldPosition, JoinHuman:** per actor.
- **Text quests and arcade:** local only; text quests are off in multiplayer.

### Unsaved state (matters for lockstep only)

- **Lost if a save or State is taken while held:** `THuman.PlanetHeldSatellite` and `SelectedHoldItem`. While held, the object is in no galaxy list.
- **Not in the per-human block:** `TradeRows`, the talk fields, `GovernmentQuestOffer` and its steps, and the government dialog cursor.
- **Not saved at all:** the dialog globals and the queued battle, video and text-quest lists.
- **Unknown:** whether the `GoodsMarket` averages behind `TradeRows` prices are saved or recomputed.
