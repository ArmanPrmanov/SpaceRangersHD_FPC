- Notes:
  - **Deviation, item 2.** The roadmap says to seed chaotic mode from the
    save. It is seeded from the clock when a galaxy is created or loaded
    instead, so reloading still rerolls, which is what the mode is for. It
    is reproducible given the seed (`--sim-seed` pins it; Phase 3 should
    record it in the command log). Revisit if chaotic games must replay from
    a save alone.
  - The object reference table relies on the original game not checking for
    bytes after the galaxy data. Not verified: load a save written by this
    build in the original `Rangers.exe` once.
  - Unresolved script values after load (13–30 per turn) are stale
    addresses from the original saves and large numbers (`rewardSeed*`),
    not missing containers. They stay as read.
  - Win32 mods can keep addresses in `vkInt` variables (see `TVarEC`); the
    table covers `vkDword` only.
  - Galaxy generation still draws from the shared stream, which UI threads
    can also advance during generation, so a seed may not reproduce a galaxy
    exactly. Replay starts from saves, so this does not affect Phase 3.
  - Cosmetic but saved: `GenerateSpaceBackground` and the hangar slot shuffle
    draw from the presentation stream and are written to the save. They are
    only called from screens, so headless hashes are unaffected; Phase 5
    deltas will see them.
  - Script builtins `rnd`, `randomize`, `randseed` (lowercase, in
    `EC_Expression`) still use `System.Random`. The presentation-seed test
    found no effect on the three saves; game data may still call them.
  - `SF_IsFilm` and dialogue gating read UI state from scripts. Turn results
    can depend on film timing if a script branches on them; not seen in tests.
  - The user's Break click stops travel after a turn that depends on film
    timing; a replay must record it as input.
  - The first build after editing several units sometimes fails with
    "Compilation raised exception internally"; the next build succeeds.
  - `sed -i` in this shell rewrites CRLF files as LF; the Pascal sources are
    CRLF. Edit with a tool that keeps line endings.
  - New units (`aObjectRefs`, `SimulationThread`) were not run through
    `pasfmt`; the formatters are not installed here.
